- Gallery public visibility is decided server-side by gallery_items.position vs the effective plan limit (gallery_item_is_active in the SELECT policy); owners see all items. Why: downgrades never delete media, and public queries must not leak inactive items.
- Activity analytics are first-party: the browser only calls activity_heartbeat / track_activity_event RPCs (server caps time, dedupes, assigns identity); admins read via admin_activity_* RPCs. Completed actions are counted from existing tables, not client events. Why: no client-trusted durations, no duplicate tracking of facts already in the database.
- Composers delegate Back handling to the shared modal history manager and disable the Dialog root's duplicate registration; close vetoes and nested cleanup share one stack to avoid extra navigation.
- Public SELECT policies on social/profile tables never use USING (true): rows are public only when the author account is active (is_account_active / profiles.is_active), plus owner and admin. Why: suspended accounts' content must disappear server-side, and the security scanner rejects tautology policies.
